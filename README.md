# GAIA Multimodal Research Agent

A tool-using agent for the Hugging Face Agents Course final assignment. It uses **smolagents** to answer GAIA benchmark questions, handle attached files, and submit answers to the course scoring API.

## How it works

1. **Fetch tasks:** the Gradio app reads questions from a local **questions.json** when available, otherwise from the course API.
2. **Handle attachments:** files are downloaded from the course API, with a gated GAIA dataset fallback when needed.
3. **Reason and use tools:** a **CodeAgent** selects research, file-processing, or multimodal tools and can use Python for calculations.
4. **Format the answer:** the candidate is cleaned and passed through a second model call for exact-answer formatting.
5. **Cache and submit:** successful answers can be cached by task ID, then sent to the evaluator. The UI displays the returned score and submitted answers.

## Methods that matter

- **Tool-using agent:** smolagents CodeAgent, configured for up to 12 steps and a planning interval of 3.
- **Web research:** DuckDuckGo search, webpage retrieval, Wikipedia, and an optional Gemini-powered Google Search fallback.
- **File and multimodal tools:** pandas for CSV/Excel, pypdf for PDF text, provider-backed image analysis and audio transcription, plus YouTube captions or Gemini video analysis.
- **Exact-match formatting:** prompt rules, answer cleanup, and a second model call attempt to produce the required bare answer. This improves formatting consistency but does not guarantee factual correctness.
- **Resilience:** one retry for empty/error answers, short delays between requests, and an optional local answer cache.

## Run locally

Python 3.10+ is recommended. Create a virtual environment, then install dependencies:

~~~powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
~~~

For official course submission, deploy as a Hugging Face **Gradio Space** with OAuth enabled. Local execution may not reproduce the hosted OAuth and submission attribution flow.

## Configuration

Set credentials in the Space's **Settings → Variables and secrets**. Never put keys in source code.

| Variable | Use |
|---|---|
| **GEMINI_API_KEY** | Gemini, Google Search grounding and video analysis. |
| **OPENAI_API_KEY** | OpenAI model path and image-analysis fallback. |
| **HF_TOKEN** | Hugging Face inference and, if authorized, access to the gated GAIA dataset. |
| **MODEL_PROVIDER** | Optional explicit primary provider: **gemini** or **openai**. |
| **MODEL_ID** | Optional primary model ID override. |
| **SPACE_ID** | Space identifier used to generate the code URL sent with the submission. |

Without an explicit provider, the code selects Gemini or OpenAI when the corresponding key is available; otherwise it uses Hugging Face Inference, which requires **HF_TOKEN** or **HUGGINGFACEHUB_API_TOKEN**. Use a currently supported model ID for your provider.

## Evaluation and cache

The app calls the course API at https://agents-course-unit4-scoring.hf.space:

- **GET /questions** retrieves tasks.
- **GET /files/{task_id}** attempts to retrieve attachments.
- **POST /submit** sends the username, agent-code URL and answers for scoring.

The checkbox in the UI controls whether **cached_answers.json** is reused. The cache is keyed by task ID, not model or prompt configuration; disable it or remove the file when you need to rerun tasks after changing the agent.

## Limitations

- Results depend on model quality, tool output, credentials, quotas and network access.
- PDF support extracts text; OCR for scanned pages is not implemented.
- Video analysis requires Gemini; YouTube transcript retrieval requires available captions.
- Code generated by CodeAgent is executed during the agent workflow. Run it only in an environment whose permissions and isolation you understand.
- Treat the score returned by the remote evaluator as the benchmark result; successful submission alone does not establish correctness.
